# Docker в боковой панели

Плагин для DeepSeek Harness: показывает состояние Docker и ваши compose-проекты прямо в
низу боковой панели — там же, где живёт виджет «Проекты». Никуда переключаться не нужно:
контейнеры можно запускать, останавливать и смотреть их логи из этой полоски.

```
●  Docker   3/7   ⇅  ■  ▶  ↻
```

Нажмите на полоску — раскроется список проектов. Нажмите на проект — под ним появятся его
контейнеры, по одной строке на каждый: точка состояния, имя, время работы в скобках и кнопки.

## Что умеет

- **Состояние Docker** — точка в полоске и у каждого проекта:
  - в полоске это сводка: зелёная, если работает хотя бы один контейнер; жёлтая, если есть
    приостановленные или перезапускаемые; красная, если контейнер упал или Docker недоступен;
    серая, когда все контейнеры остановлены;
  - у проекта — то же самое для его контейнеров.
- **Проекты и контейнеры** — compose-проекты с раскрытием, отдельные контейнеры вне проектов,
  счётчик запущенных/всего.
- **Консоль логов** — кнопка у контейнера открывает окно с последними строками логов
  (по умолчанию 200), с кнопкой «Обновить». Закрывается крестиком, клавишей `Esc` или кликом
  по затемнению.
- **Управление** — запуск, остановка и перезапуск одного контейнера, целого проекта и сразу
  всех контейнеров (две общие кнопки левее «Обновить»).
- **Подсветка падения** — упавший контейнер подсвечивается пульсирующим красным; если проект
  свёрнут, краснеет его заголовок. Клик по строке убирает подсветку. Ваши собственные
  остановки и перезапуски ошибкой не считаются.
- **Сортировка** — кнопка в полоске открывает меню: по статусу, по имени, по проекту.
- **Закрепление** — звезда у проекта поднимает его в начало списка.
- **Бейдж «здесь»** — отмечает проект, в котором вы сейчас работаете (по папке текущего чата).
- Раскрытие полоски, раскрытие проектов, сортировка и закрепления сохраняются между
  перезагрузками.

## Настройки

Настройки живут в **Настройки → Docker** (с иконкой Docker) и применяются сразу:

| Настройка | Значения | По умолчанию |
|---|---|---|
| Язык | Авто / English / Русский | Авто |
| Интервал обновления | выкл, 2, 5, 10, 30 секунд | 5 с |
| Скрывать остановленные проекты | вкл/выкл | выкл |
| Скрывать пустой виджет | вкл/выкл | выкл |
| Плотность | компактно / обычно / свободно | компактно |
| Размер шрифта | 11 / 12 / 13 / 14 px | 12 |
| Подробные строки | вкл/выкл | выкл |
| Счётчик контейнеров | вкл/выкл | вкл |
| Счётчик в проекте | вкл/выкл | вкл |
| Время работы контейнера | вкл/выкл | вкл |
| Кнопки «запустить/остановить всё» | вкл/выкл | вкл |
| Отдельные контейнеры | вкл/выкл | вкл |
| Подтверждать «остановить все» | вкл/выкл | вкл |
| Строк логов в консоли | 200 / 500 / 1000 / 2000 | 200 |
| Порог «зависшего» контейнера | выкл, 5, 15, 60 минут | выкл |
| Звук при падении | выкл / два тона / перезвон / сирена / пинг | выкл |

Пара пояснений:

- **Язык**: «Авто» берёт язык Harness (а он стартует от языка системы). Можно заставить
  виджет говорить по-английски или по-русски независимо от остального интерфейса.
- **Подсветка падения** не срабатывает, если вы сами остановили или перезапустили контейнер:
  обычная остановка (`exit 130/143`) и принудительное убийство `exit 137` (без OOM) падением
  не считаются, а действия из виджета на 90 секунд исключают затронутые контейнеры из проверки.
- **Порог «зависшего»**: если у работающего контейнера давно нет новых строк логов, точка
  становится жёлтой.
- **Счётчик в проекте**: строка «запущено N из M» считает все контейнеры проекта, включая
  разовые (`docker compose run`) — поэтому их может быть больше, чем сервисов. Если счётчик
  мешает, выключите его здесь, он исчезнет из строк проекта.
- **Остановка в цикле перезапуска**: если контейнер постоянно перезапускается, Docker
  отклоняет обычный `docker stop`. Виджет на мгновение снимает политику перезапуска,
  останавливает контейнер и возвращает политику обратно.
- **Звук при падении**: выбранный сигнал можно прослушать кнопкой-динамиком рядом со списком.

## Где хранятся настройки

Настройки общие для всего профиля: Harness хранит их в
`$DSH_HOME/storages/docker-sidebar/prefs.json`, поэтому один и тот же профиль в разных
браузерах видит одни и те же значения. В браузере остаётся рабочая копия
(`localStorage`, ключ `docker-sidebar:settings`) — если файл профиля недоступен, виджет
продолжает работать. Страница настроек показывает, где сейчас лежат значения.

Служебное состояние (что раскрыто, сортировка, закрепления, непросмотренные падения) тоже
хранится в браузере: `docker-sidebar:open`, `docker-sidebar:expanded`,
`docker-sidebar:alerts`.

## Проверка окружения

Если Docker не установлен или `docker` нет в `PATH`, виджет не показывает непонятную
ошибку, а подсказывает, что делать. То же самое, если установлен, но не запущен Docker
Desktop / служба docker. Статус окружения виден и в настройках.

## Установка

```
plugin_manager: { action: install_bundle, target: "<полный путь к этой папке>" }
```

`docker` должен быть доступен процессу Harness. После установки или обновления файлов
хост-часть нужно перезапустить (переключить строку плагина в **Plugins**), а страницу —
обновить.

На странице настроек видно версию установленного плагина («Версия плагина 1.2.0»). Если на
другом компьютере версия отличается, обновите папку плагина:

```
git fetch origin
git reset --hard origin/main
```

(или клонируйте репозиторий заново) и перезапустите плагин. Обычный `git pull` может не
сработать, если локальная копия осталась от старой истории — тогда поможет только
`reset --hard`.

## Безопасность

- `docker` запускается из процесса Harness, который и так управляет контейнерами.
- Каждая команда — массив аргументов, без shell и подстановок строк.
- Идентификаторы контейнеров и имена проектов проверяются, список действий закрытый.
- Виджет не удаляет образы, тома, сети и контейнеры.
- Настройки проверяются по формату и размеру перед записью.

## Для разработчика

Маршруты хост-части (регистрируются на общей шине Connection, работают и в веб-, и в
десктоп-оболочке):

| Маршрут | Метод | Что делает |
|---|---|---|
| `/api/dsh-docker/state` | GET | состояние движка, проекты, контейнеры |
| `/api/dsh-docker/action` | POST | действие над контейнером, проектом или всеми сразу |
| `/api/dsh-docker/diag` | GET/POST | диагностика браузерной части |

Действия: `container.start` / `container.stop` / `container.restart` / `container.logs`
(с `tail`), `project.start` / `project.stop` / `project.restart`, `all.start` / `all.stop` /
`all.restart`, `logs.lastAt` (с `ids`), `prefs.get` / `prefs.set`, `refresh`.

`GET /dsh-docker-diag` — отдельный маршрут только для локального оператора (loopback), отдаёт
последние 20 отчётов браузерной части.
